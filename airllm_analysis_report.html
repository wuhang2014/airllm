Three ideas do almost all the work: (1) a one-time offline "split" that rewrites any HF checkpoint into one safetensors file per module; (2) forward hooks on the meta-device model that materialize/evict each module around its execution, with a background thread prefetching the next shard; (3) letting transformers own the forward pass, so AirLLM never re-implements attention/rotary/cache logic and new architectures work day-0. Everything else — per-expert hooks, mmap embeddings, FP8/MXFP4 handling, streamed LoRA, chunked cross-entropy — is a consequence of pushing those three ideas into frontier models.

2Core architecture: hook-driven layer streaming

airllm_base.py:58 — AirLLMBaseModel wraps a real transformers model and owns weight logistics only.

2.1 The meta-device trick

The model is instantiated under accelerate.init_empty_weights(include_buffers=False), so every Parameter lives on the meta device — zero bytes allocated (airllm_base.py:296). Non-persistent buffers (rotary inv_freq etc.) are computed and moved to CUDA once (airllm_base.py:370). A factory-fallback chain (AutoModelForImageTextToText → CausalLM → MultimodalLM → AutoModel, airllm_base.py:266) plus a "does the module tree actually match our layer map?" check (airllm_base.py:251) makes one code path cover dense, MoE, and VL checkpoints.

2.3 Prefetch pipeline

  • Single-worker ThreadPoolExecutor submits _load_streamed_layer(idx+1) while idx computes (airllm_base.py:890-894) — ~10% end-to-end win, the disk read overlaps GPU compute.
  • Pinned (page-locked) host memory only for shards ≤ max_pinned_layer_bytes = 2GB (airllm_base.py:75): two prefetched 17GB MoE layers in flight would otherwise lock ~34GB of RAM that can never be paged out — a deliberate cap with graceful fallback to pageable on RuntimeError.
  • Tied embeddings special case: lm_head shares the embed weight, so the embed stays resident and only decoder layers + norm stream (airllm_base.py:756-764).

2.4 Why this design wins

Design payoff

Because transformers drives the forward, AirLLM carries zero per-architecture math code — no attention kernels, no rope, no KV-cache bookkeeping. A model released today works as soon as transformers supports it; the only per-model knowledge is a module-path map (layer_names_dict). Legacy remote-code architectures (ChatGLM, QWen, Baichuan, InternLM) and two frontier ones (Kimi K3, Qwen4Exp) are the only subclasses — each is essentially just a dict of paths (see airllm_kimi_k3.py:18, 32 lines total).

3Checkpoint splitting: the offline half

utils.py:528 split_and_save_layers() — a one-time, resumable ETL from "whatever HF ships" to "one safetensors file per streamed module".

  • Format-agnostic input: indexed safetensors / single-file safetensors / pytorch .bin(+index) all normalized into a weight_map (utils.py:549-572); shards are downloaded on demand via snapshot_download(allow_patterns=…) so a 360GB repo never needs all shards resident at once.
  • Longest-prefix ownership: each tensor key is assigned to its owning module via layer_owner() (utils.py:400) — critical so a nested PLE table under a decoder layer isn't swallowed into that layer's shard and later dragged onto the GPU (utils.py:764-767).
  • Crash-safe resume: each output gets a <name>.safetensors.done marker; re-runs re-check all markers and only re-save missing/corrupt ones (persist/safetensor_model_persister.py:20).
  • Passthrough hard-linking: if a checkpoint already ships exactly one module per shard (Kimi K3: one ~17GB shard per decoder layer), the splitter hard-links instead of rewriting — avoiding duplicating 1.5TB+ and hours of I/O for byte-identical output (utils.py:633-654, 692-709). Degrades gracefully: hardlink → symlink → copy (utils.py:501).
  • Shard-order correctness: modules are stably sorted by the last shard they touch, so a vision tower interleaved in the shard sequence can't silently truncate another module's tensor set (utils.py:600-612); layers spanning multiple shards (fp8 weight + scale pairs) load every shard up to their max (utils.py:713-719).
  • Space management: pre-flight disk check with compression-aware estimates (utils.py:447); delete_original=True streams deletions of consumed originals to halve peak disk.

4Per-expert streaming for MoE

airllm_base.py:778 _setup_expert_streaming() — the trick that takes Kimi K3 from "impossible" to 3.72GB.

A sparse MoE layer holds hundreds of experts but routes each token to a handful (K3: 896 experts, 16 active). Materializing the whole layer is ~55GB expanded; a token touches ~1GB. Because the router calls each selected expert as its own module (and skips the rest), a forward hook per expert loads exactly the experts that actually run:

  • Enabled simply by an expert_prefix entry in the layer map (airllm_kimi_k3.py:24) + safetensors' ability to seek to individual tensors: load_layer_subset() (utils.py:415) reads one expert's few MB out of a ~17GB layer file without touching the rest.
  • Layer-level hooks then load only the non-expert keys of the layer (attention, norms, router) via _non_expert_keys (airllm_base.py:874).
  • Eviction bookkeeping: since experts manage their own lifetime, the layer post-hook releases only the tensors it placed — never module.to('meta'), which would evict experts/cpu-resident children too (airllm_base.py:896-907).
  • Contrast — Qwen4Exp ships experts as 3D packed tensors on one module, not a ModuleList, so Kimi-style per-expert hooks don't apply; a whole MoE layer (a few GB bf16) streams instead (airllm_qwen4_exp.py:39-41). Honest architectural note in the docstring.

6Quantization: two distinct paths

6.1 Self-compression (bnb) — for I/O speed, not VRAM

Since the bottleneck is disk loading, AirLLM quantizes weights only at split time — NF4 (blocksize 64) or int8 (blocksize 2048) via bitsandbytes — shrinking bytes-to-load ~4×/2× for up to 3× faster inference with negligible loss (utils.py:470-489). Activations stay high-precision, which is why accuracy holds. Quant-state is serialized alongside (including a local re-implementation of bnb's broken as_dict, utils.py:43) and reconstructed per-layer at load through AutoHfQuantizer.create_quantized_param (airllm_base.py:611-615).

6.2 Pre-quantized checkpoints (FP8 / MXFP4) — load packed, decompress on GPU

  • Verbatim placement: anything not a plain high-precision float — fp8 weights, packed 4-bit ints, scales, g-idx — is moved to device without dtype cast; casting would silently destroy the quantization (airllm_base.py:633-648, _should_load_verbatim).
  • PCIe-optimized decompression: MXFP4 payloads are transferred still-packed, then expanded on the GPU — 4× less PCIe traffic than transferring expanded weights (airllm_base.py:489-543).
  • Hook surgery: compressed-tensors normally registers a whole-model decompress-on-first-forward hook, which would re-expand every packed module (a K3 layer → ~56GB) and defeat per-expert streaming; AirLLM removes it and decompresses per-module itself (airllm_base.py:355-361). Mixed-layout checkpoints where "quantized" modules actually ship bf16 get their plain weight Parameter restored (airllm_base.py:459).

7Training huge models on tiny GPUs: streamed LoRA

airllm_lora.py — HF Trainer/PEFT keep the whole autograd graph (or all 4-bit weights) resident; AirLLM instead applies gradient-checkpointing thinking to weight streaming.

7.1 Custom autograd Function with disk recompute

_StreamedModule (airllm_lora.py:35): forward runs the streamed module under no_grad and returns CPU-detached output; backward re-materializes the layer from disk and runs a real forward with grad to backprop into the LoRA adapters, returning d_hidden to CPU. Hidden states are CPU tensors between layers, so a 64-layer graph never pins 64 hidden states in VRAM. Eviction + prefetch of the previous layer are scheduled inside backward (reverse order) — the pipeline is direction-symmetric.

7.2 LoRA without PEFT

LoRALinear (lora_linear.py:41) wraps and keeps the original weight Parameter object, so AirLLM's shard loader (<module>.weight keys) still works while the base tensor swaps disk↔meta; only lora_A/B (+ their AdamW state) stay resident on GPU. PEFT is explicitly rejected because it materializes full base weights. LoRAPackedExperts (lora_linear.py:98) extends this to Qwen4Exp's 3D packed expert tensors — matmuls only on routed experts' rows. Defaults are VRAM-aware: packed-expert LoRA is off by default (48 layers × 512 experts × r16 ≈ 5.5GB adapters + 22GB fp32 Adam), and MoE runs eager experts to avoid grouped-mm's autograd allocating full-size frozen dW (airllm_lora.py:445-451).

7.3 Chunked cross-entropy

Qwen3.8's lm_head is 248320×5120 (2.54GB bf16); naive logits at seq 2048 add ~2GB fp32. chunked_linear_cross_entropy (chunked_ce.py:19) walks the vocabulary in chunks with a running logaddexp log-sum-exp, never materializing [N, vocab], and recomputes the same chunks in backward for d_hidden. Both hidden and weight may live on CPU — rows of embed/lm_head are gathered from host RAM (cpu_resident in airllm_lora.py:85).

Result

125B MoE trains under 6GB (RTX 3060 Ti-class); 27B dense in ~2GB at seq 512. Peak VRAM = one streamed layer + adapters + optimizer.

9MacOS / MLX backend

A parallel path for Apple Silicon: AutoModel routes to AirLLMLlamaMlx on darwin (auto_model.py:57), a compact from-scratch Llama implementation in mlx that reuses the same split shards through an MlxModelPersister (.npz variant). Same lifecycle discipline — load layer, compute, free — via explicit mx.eval/gc management rather than hooks. Trade-off: Llama-family only, and separate model code to maintain.

10Design principles worth stealing

  • Own logistics, not math. By hooking module boundaries on a meta-device model, AirLLM outsources all architecture-specific computation to transformers. Per-model cost ≈ one dict of module paths. This is why "most new models work the day they're released."
  • Disk is a memory tier. The split format is designed for random access (one file per module; per-tensor seek within files), making "load exactly what runs" cheap — the enabler for per-expert streaming and mmap gathers.
  • Skip work that's already done. Passthrough hard-linking when shards already match the target layout; .done markers for resume; on-demand shard download; delete-as-you-go for originals.
  • Quantize for bytes, not compute. Recognizing the bottleneck is I/O lets weight-only compression deliver speed without activation-quantization accuracy pain.
  • Checkpointing generalizes. The training path is gradient checkpointing taken to its logical extreme — recompute = re-load from disk; intermediates live on CPU; the fused-CE avoids the other classic blowup ([N,vocab] logits).
  • Budget scarce resources explicitly. Pinned-memory 2GB cap, verbatim-vs-cast load policy, per-hook release lists instead of blanket .to(meta).

11Trade-offs & risks

Throughput

Layer loads dominate; decode is roughly disk-bandwidth ÷ bytes-per-layer (tokens/sec, not tens). AirLLM optimizes feasibility (biggest model on smallest card), not serving latency. Prefetch + compression only partially mitigate.

First-run cost

The split pass needs ~1× checkpoint size in free disk (unless passthrough applies) and hours for T-scale models; huge host RAM is assumed for some paths (K3 experts, Flash-Next needs ≥64GB machine for the mmap'd table).

Global mutable state

ModelPersister singleton (persist/model_persister.py:4), class-attribute stashing in _StreamedModule (airllm_lora.py:43) and _ChunkedCE, plus monkeypatches of nn.Embedding.__init__/Tensor.scatter — all process-global and not thread-safe. Acceptable for a CLI/library-of-one-model-per-process, but a hazard for embedding AirLLM inside a server.

Maintenance surface

The compatibility shims (§8) are tied to exact upstream behavior and will need chasing every transformers release; two backends (CUDA-hooks + MLX) and the aux training lab (anima_100k/rlhf, pinned to 2023-era deps in requirements.txt) drift independently of the packaged core.

Coverage notes

Packed-tensor MoE (Qwen4Exp) streams whole layers, not experts; MLX path is Llama-only; prefetch disabled under bnb compression; one repo bug spotted on read: remove_real_and_linked_file can reference an unassigned targetpath (utils.py:491-497) when the path is not a link.
